## 3. Contribution & Review Lifecycle
1. **Branching**: Create feature branches with format `feature/<module_id>-<short-description>`.
2. **Pull Requests**: Submit PRs targeting `main` using the repository PR template.
3. **Approvals**: Minimum 1 Lead review and verification from the Testing & QA team before merging.
4. **Code Quality**: Code must follow repository standards defined in `CONTRIBUTING.md` and `docs/coding_standards.md`.
